# 구매 체크리스트 v1 — Priority Gate 재탕 스펙

> 대상 카테고리 5개(토너·썬크림·세럼·로션크림·클렌저). **립케어는 프로젝트에서 제거.**
> 룰 조건·문구·CTA의 원본은 `skincare_ruleset_v12.md` §2이며, 이 문서는 **어떤 룰·질문을 어느 제품군 체크리스트에 노출하는지**만 정의한다. 여기 없는 내용은 노출하지 않고, 여기 있는 내용은 가공 없이 그대로 노출한다.

---

## 0. 목적과 접근

### 0.1 최초 목적 (장기 — product matrix 구축 후)

구매 체크리스트는 원래 "성분·전문용어를 아는 사람"이 아니라 "불편만 아는 사람"을 위한 화면이다.

1. **일상용어 → 전문용어 매핑.** "백탁이 싫어요" → 유기자차. 쿠션·스틱·파우더 같은 제형 선택도 직접 묻지 않고 "가지고 다니면서 쓸 건가요?"처럼 **간접 질문**으로 받아낸다.
2. **품질 기준은 큐레이션으로 해결.** SPF·PA 수치, 용기 형태(불투명) 같은 항목은 사용자에게 묻지 않고 서비스가 미리 걸러서 보여준다.
3. **정보 허브.** "선크림 하나 사는데 SPF, PA, 백탁, 눈시림까지 봐야 하나요?" — 제품군별로 확인해야 할 기준을 한곳에 모아 보여주는 것 자체가 콘텐츠다.

### 0.2 현재 접근 (v1 — 임시)

product matrix가 아직 없으므로, 위 목적은 보류하고 **priority gate(v12) 질문·룰을 제품군별로 역추적해 재탕**한다.

- 제품군마다 "그 제품군에 대한 결론(도입·전환·중단·사용법)을 내는 룰"만 고르고, 그 룰들의 조건이 참조하는 질문만 노출한다.
- **정확히 해당 내용만 나온다.** 새 룰·새 질문·문구 수정·fallback 카드 추가 없음.
- 평가 로직도 priority gate와 동일(EXCLUDED veto → REQUIRED AND, 미응답 REQUIRED는 실패).

### 0.3 공통 게이트

모든 제품군 체크리스트에 **010(의료 라우팅)·020(치료 중 안내)** 를 포함한다.

- 사유 ①: 구매를 멈춰야 하는 상황(치료 수준)은 어느 제품군에서든 첫 번째 판단이다.
- 사유 ②: 티어 매크로가 Q-D1·Q-D5를 EXCLUDED로 쓰므로 이 질문들은 어차피 노출된다. 010·020이 없으면 "심한 여드름"이라고 답한 사용자가 아무 카드도 못 받는 dead-end가 생긴다.

## 3. 구현 메모 (스키마 매핑 — 구현 작업에서 확정)

- **Question 행 재사용, QuestionVariant만 `screen=context`로 신규 시드.** 응답은 Question 단위(UserResponse.questionId)라 **루틴 점검에서 답한 값이 체크리스트에 미리 채워지고, 어느 쪽에서 바꿔도 서로 반영**된다(의도된 동작).
- 변형 배치: 전 카테고리 공통(Q-D1·Q-D5)은 `uiSection=basic, category=null` 1개. 나머지는 필요한 제품군마다 `category=<키>` 변형을 각각 시드(스키마상 (questionId, screen, uiSection, category, sortOrder) 조합별 1행 — 예: Q-R3 4개, Q-S2 2개). 피부 상태·습관 질문(Q-R*)은 basic, 제품·목적 질문(Q-C/T/S/M/U/G)은 category 섹션.
- 카테고리→룰 매핑의 원본은 이 문서 §1. 구현은 백엔드 코드 상수 `CHECKLIST_RULE_SORT_ORDERS`(category-decision.service.ts)로 확정 — 시드와의 정합성은 seed-data.spec이 교차 검증한다.
- CTA 버튼은 카드에 그대로 노출하되, 체크리스트 화면에서는 클릭 시 이동 대신 "개발중입니다." 토스트를 띄운다(제품군 페이지 간 순환 링크 방지, product matrix 전까지).
- 매칭 0건이면 기존 빈 상태 문구("답변을 선택하면 결론이 표시됩니다") 사용. fallback 룰을 만들지 않는다.
- (해결됨) category-decision 백엔드 기존 결함 2건(기본 카테고리 toner 404 falsy-zero, `category.selected` 질문 부재 500)은 구현 과정에서 정리 완료 — `category.selected` 의존은 제거됐고 카테고리는 URL 파라미터로만 결정한다.
