# Landing Page 구성

> 사용자가 제품군을 몰라도, 고민이나 현재 상태에서 자연스럽게 시작할 수 있게 만드는 진입 페이지

랜딩 페이지는 총 6개 섹션으로 구성한다.

## Section 1 — Hero / Segment Entry

> 서비스의 첫 진입 화면. 사용자가 자신의 상황에 맞는 시작점을 고르게 한다.

### Nav Bar

상단에는 고정형 Nav Bar를 둔다.

```txt
초기 상태:  배경 투명 / 가운데 정렬 메뉴 / 우측 CTA 버튼
스크롤 이후: 반투명 배경 + 둥근 pill 형태 + blur 효과
```

### Hero Title

> 고민부터 시작해도 돼요

어떤 제품이 필요한지 몰라도 괜찮아요.  
지금 상태와 고민에 맞춰 무엇을 먼저 해야 하는지부터 정리하고, 필요하면 카테고리로 이어드립니다.

### Segment 선택 영역

Hero 아래에 2x2 구조의 세그먼트 선택 카드를 배치한다.

```txt
[ 어디서부터 손댈지 모름 ]    [ 고민은 있는데 카테고리를 모름 ]
[ 이미 찾는 제품군이 있음 ]   [ 실패 원인 추적형 ]
```

| 세그먼트                      | 설명                                               | 이동                       |
| ----------------------------- | -------------------------------------------------- | -------------------------- |
| 어디서부터 손댈지 모름        | 지금 무엇부터 정리해야 할지 모르는 사용자          | Priority Gate              |
| 고민은 있는데 카테고리를 모름 | 문제는 있지만 어떤 제품군이 필요한지 모르는 사용자 | 고민 입력 / Concern Mapper |
| 이미 찾는 제품군이 있음       | 선크림, 세럼 등 보고 싶은 제품군이 있는 사용자     | Product Matrix             |
| 실패 원인 추적형              | 특정 제품 사용 후 문제가 생긴 사용자               | Reaction Traceback         |

## Section 2 — Priority Gate 소개

> 지금 제품을 사도 되는 상태인지 먼저 확인하는 기능 소개

레이아웃: 좌측 설명 + 우측 이미지

### 설명 문구

제품을 고르기 전에, 지금 사도 되는 상태인지 먼저 확인해요.

최근 자극, 루틴 변경, 선크림 사용, 클렌징, 보습 상태를 확인해  
새 제품을 사야 할지, 잠시 보류해야 할지 알려줍니다.

### 핵심 포인트

- 새 제품 구매 가능 여부 판단
- 루틴 안정화 필요 여부 확인
- 선크림 / 클렌징 / 보습 우선순위 안내
- 진단이 아니라 gate

### 이미지 영역

`[Priority Gate 화면 이미지 자리]`

## Section 3 — Context 소개

> 제품군에 맞는 질문만 보여주는 개인 맥락 입력 기능 소개

레이아웃: 좌측 이미지 + 우측 설명

### 설명 문구

모든 제품군에 같은 질문을 하지 않아요.

립밤을 고르는데 피부 타입을 묻지 않고,  
선크림을 고를 때는 눈시림, 백탁, 메이크업 궁합을 묻습니다.

제품군에 맞는 질문만 보여주고, 그 답변을 이후 필터링에 반영합니다.

### 핵심 포인트

- 제품군별 질문 자동 변경
- 불필요한 질문 제거
- 사용 장소, 시간대, 휴대성, 민감도 반영
- Context 답변을 Product Matrix 필터로 연결

### 이미지 영역

`[Context 질문 화면 이미지 자리]`

## Section 4 — Product Matrix 소개

> 제품 후보를 가격대별 Tier List 형태로 비교하는 기능 소개

레이아웃: 좌측 설명 + 우측 이미지

### 설명 문구

제품을 끝없이 나열하지 않아요.

좋은 제품의 조건과 개인화 필터를 기준으로  
가격대별 추천 후보를 한 번에 비교할 수 있게 보여줍니다.

### 핵심 포인트

- 제품군 Select
- 좋은 제품의 조건 태그
- 개인화 필터
- 가격대별 Tier List
- ✓ 적합 / △ 주의 / ✕ 비추 표시

### 이미지 영역

`[Product Matrix 화면 이미지 자리]`

## Section 5 — Reaction Traceback 소개

> 실패 경험을 다음 선택에 반영하는 원인 후보 추적 기능 소개

레이아웃: 중앙 정렬 제목 + 설명 + 이미지

### 설명 문구

> 어떤 제품 때문에 뒤집어졌는지 모르겠다면

문제 있었던 제품과 괜찮았던 제품을 함께 등록하면,  
공통 성분과 차이점을 비교해 원인 후보를 추측합니다.

확정 진단이 아니라, 다음 선택에서 피해야 할 가능성을 줄이는 도구입니다.

### 화면 요소

`[문제 상품 등록 +]` `[괜찮은 상품 등록 +]`

- 바코드 스캔으로 상품 찾기
- 브랜드 > 제품군 > 제품 선택
- 제품명 직접 검색
- 성분 후보 비교

### 이미지 영역

`[핸드폰 바코드 스캔 이미지 자리]` 또는 `[문제 상품 vs 괜찮은 상품 비교 UI 자리]`

## Section 6 — Concern Mapper / 고민 유형 캐러셀

> 고민은 있지만 제품군을 모르는 사용자를 위한 진입 섹션

레이아웃: 고민 유형별 태그가 좌우로 움직이는 무한 캐러셀

### 설명 문구

> 고민부터 시작해도 돼요

어떤 제품이 필요한지 몰라도 괜찮아요.  
고민 유형을 고르면 무엇을 먼저 점검해야 하는지부터 정리해드려요.

### 캐러셀 구조

```txt
일회성 트러블  [뾰루지] [여드름] [붉어짐] [뒤집힘] [트러블 반복]
일상 불편      [건조] [당김] [각질] [번들거림] [입술 트임]
화장 / 꾸미기  [화장 뜸] [밀림] [선크림 추천] [쿠션 추천] [립 제품]
컴플렉스       [잡티] [다크서클] [홍조] [모공] [피부톤]
```

### 인터랙션

- 각 줄은 좌우로 움직이는 무한 캐러셀
- 모바일 스와이프 / 데스크톱 드래그 또는 자동 흐름
- 초기에는 태그 형태, 추후 카드 또는 사진 + 텍스트 형태로 확장 가능

### 구현 방식 (MVP)

고민 태그는 **MVP에서 프론트엔드 상수**로 관리한다. DB 테이블 없음.

Concern Mapper는 제품군 라우터가 아니라 **Priority Gate preset**으로 동작한다.

태그 클릭 시 흐름:

1. `session_events`에 `concern_clicked` 이벤트 저장
2. `user_facts`에 `flow.concern` 저장 (`source: "concern"`)
3. 관련 `preset_facts`를 초기 선택 상태로 저장하거나 프론트 상태에 유지
4. `route_target = "priority_gate"`면 S02로 이동하고 관련 Life / 루틴 질문을 우선 노출
5. `route_target = "category_decision"`면 `category.selected = suggested_category`를 seed한 뒤 S03로 이동
6. `suggested_filters`는 Product Matrix 직행용이 아니라, 이후 Category Decision CTA에서만 `CONCERN_PRESET` 힌트로 반영

```
[여드름] 클릭
  → session_events: concern_clicked { concern: "acne" }
  → user_facts: flow.concern = "acne"
  → preset_facts: life / reaction / routine 질문 우선 노출
  → Priority Gate
  → 게이트 결과에 따라 루틴 점검 / 클렌저 추천 / Category Decision / Product Matrix
```

`preset_facts`는 확정 답변이 아니라 초기 선택 상태다. 이후 사용자가 직접 답한 Priority Gate / Context 답변이 최종값으로 취급된다.

추후 태그 목록 변경이 잦아지면 DB로 이관 가능. MVP에서는 코드 변경으로 충분하다.

## 핵심 방향

랜딩 페이지는 제품 추천을 바로 시작하지 않는다.  
사용자가 아래 세 가지를 직관적으로 이해하게 만드는 것이 목표다.

- 지금 무엇부터 봐야 하는지
- 제품군을 몰라도 시작할 수 있는지
- 실패 경험을 다음 선택에 반영할 수 있는지

## 핵심 Feature (우선순위 순)

### Feature 1 — Priority Gate

> "지금 제품을 사야 하는가?" 를 먼저 판별하는 체크리스트형 게이트

- "Life / 루틴", "사용 중인 Skin Care 제품"체크리스트와 최종 결론 제품군의 3Box 레이아웃으로 이루어져있다.
- Life / 루틴 항목은 "지금 사도 되는 상태인가"를 판단하고,
- 제품 항목은 "무엇을 사지 말아야 하는가 / 어떤 제품군부터 봐야 하는가"를 판단한다.

#### 개념적인 우선 순위

1. 최근 자극 / 문제 반응 확인
2. 자외선 노출 / 야외 활동 확인
3. 선크림 사용 / 덧바름 확인
4. 클렌징 방식 확인
5. 눈가 자극 여부 확인
6. 피부 장벽 / 건조 / 당김 확인
7. 메이크업 / 선크림 궁합 확인
8. 브러시 / 퍼프 위생 확인
9. 밤 루틴 / 침구 위생 확인
10. 기능성 고민 확인
11. 제품군 선택
12. 제품군 내부 필터링

#### A. Life / 루틴 체크리스트

| 체크 항목      | 질문 예시                                          |
| -------------- | -------------------------------------------------- |
| 최근 자극 여부 | 최근 따가움, 붉어짐, 가려움 같은 문제가 있나요?    |
| 야외 활동      | 하루 기준, 낮에 밖에 있는 시간은 어느 정도인가요?  |
| 선크림 사용    | 외출할 때 선크림을 바르나요?                       |
| 선크림 덧바름  | 선크림을 가지고 다니면서 덧바르나요?               |
| 클렌징 방식    | 1차 세안 제품(오일/밤/워터/패드)을 따로 쓰나요?    |
| 거품 세안 여부 | 클렌징 폼을 쓸 때 거품을 충분히 내서 쓰나요?       |
| 눈가 자극      | 화장이나 세안 중 눈이 따갑거나 눈에 들어가나요?    |
| 건조 / 당김    | 세안 후 당김, 건조, 따가움 같은 문제가 있나요?     |
| 메이크업 여부  | 선크림 위에 베이스 메이크업을 자주 올리나요?       |
| 도구 위생      | 브러시 세척한 지 얼마나 됐나요, 퍼프는 산 지 얼마나 됐나요? |
| 배갯잎 교체    | 배갯잎은 마지막으로 바꾼 지 얼마나 됐나요?         |
| 아침 얼굴 상태 | 아침에 일어났을 때 얼굴 상태는 어떤 편인가요?      |
| 잠들기 전 루틴 | 잠들기 전에 스킨케어 루틴을 하고 자는 편인가요?    |
| 잠들기 전 세안 | 잠들기 전에 세안은 하고 자는 편인가요?             |
| 현재 고민      | 지금 가장 해결하고 싶은 고민은 무엇인가요?         |

#### 체크리스트 별 실제 결과물

| 체크 결과                                             | 실제 결과물                                                    |
| ----------------------------------------------------- | -------------------------------------------------------------- |
| 최근 자극 반복 / 문제 반응 있음                       | 지금은 새 제품보다 피부 반응 안정화가 먼저예요.                |
| 야외 활동 시간 많음 + 선크림 불안정                   | 세럼보다 선크림 루틴이 먼저예요.                               |
| 외출 시 선크림을 자주 생략함                          | 외출할 때 바를 수 있는 선크림을 먼저 찾아야 해요.              |
| 1차 세안 제품 없이 지우는 편임                        | 새 제품보다 클렌징 루틴 점검이 먼저예요.                       |
| 눈가 자극 경험이 자주 있음                            | 저자극 세안/선크림 기준을 같이 봐야 해요.                      |
| 세안 후 당김 / 건조 / 따가움 반복                     | 기능성 제품보다 보습 루틴 고정이 먼저예요.                     |
| 메이크업 자주 함 + 밀림/들뜸 있음                     | 선크림, 보습제, 베이스 궁합을 같이 봐야 해요.                  |
| 브러시 세척 시점이 오래됐거나 퍼프 사용 기간이 김      | 제품 추천 전에 도구 위생도 같이 점검해요.                      |
| 잠들기 전 루틴이 비어 있거나 세안을 자주 빼먹고, 배갯잎 교체 시점이 오래됨 | 제품 추천 전에 밤 루틴과 침구 위생도 같이 점검해요.            |
| 아침에 번들거림이나 새 트러블이 자주 보임              | 밤 루틴과 침구 위생을 함께 점검해요.                            |
| 세럼 / 앰플 / 에센스 등 기능성 제품을 여러 개 사용 중 | 새 기능성 제품은 잠시 보류하고 루틴을 단순화하는 게 좋아요.    |
| 레티놀 / 비타민C / AHA / BHA 제품을 동시에 사용 중    | 자극 가능성이 높아 새 세럼이나 필링 제품은 보류하는 게 좋아요. |
| 기본 루틴 안정 + 최근 자극 없음                       | 지금은 기능성 제품군을 봐도 괜찮아요.                          |
| 비슷한 역할의 제품을 이미 여러 개 보유 중             | 새로 사기보다 기존 제품을 먼저 정리해요.                       |

### Feature 2 — Category Decision Matrix

> **"이 카테고리에서 무엇을 봐야 하는가"와 "지금까지 정보로 필터링된 제품 후보"를 한 화면에 보여주는 제품군별 판단 매트릭스**

Category Decision Matrix는 **3개의 공통 박스 구조**로 구성된다.

1. **기본 확인**
2. **카테고리 기준**
3. **판단 결과**

#### 개념적인 우선순위

1. Priority Gate 결과 확인
2. 사용자가 볼 제품군 확인
3. 기본 사용 맥락 확인
4. 제품군별 핵심 기준 확인
5. 피해야 할 조건 확인
6. 가격대 / 제형 / 사용감 필터링
7. Good fit 판단
8. 제품 후보에 적합도 태그 부여

---

#### Box 1. 기본 확인

> 제품군과 상관없이 제품 선택 전에 필요한 최소 맥락을 확인한다.

단, 모든 질문을 모든 제품군에 강제로 묻지 않는다.  
예를 들어 립케어를 고르는데 피부 타입을 묻는 것은 부자연스럽기 때문에 제외한다.

| 질문 항목          | 질문 예시                                               |
| ------------------ | ------------------------------------------------------- |
| 사용 장소          | 주로 집에서 쓸 건가요, 밖에서 쓸 건가요?                |
| 사용 시간          | 아침에 쓸 건가요, 밤에 쓸 건가요?                       |
| 휴대성             | 외출 시 들고 다니며 사용할 예정인가요?                  |
| 이전 실패 경험     | 이전에 불편했던 사용감이나 성분이 있나요?               |
| 피하고 싶은 사용감 | 끈적임, 답답함, 향, 화한 느낌 중 피하고 싶은 게 있나요? |

---

#### Box 2. 카테고리 기준

> 선택한 제품군에서 실제로 봐야 하는 기준을 확인한다.

제품군마다 질문은 다르게 노출된다.

##### 선크림

| 체크 항목     | 질문 예시                                             |
| ------------- | ----------------------------------------------------- |
| SPF / PA      | 야외 활동이 많은 편인가요?                            |
| 눈시림        | 선크림을 바르면 눈이 시린 편인가요?                   |
| 백탁          | 백탁이 있으면 사용하기 어려운가요?                    |
| 사용감        | 끈적임이나 답답함 때문에 선크림을 생략한 적이 있나요? |
| 메이크업 궁합 | 선크림 위에 베이스 메이크업을 하나요?                 |
| 휴대성        | 밖에서 덧바를 수 있는 형태가 필요한가요?              |

##### 세럼

| 체크 항목   | 질문 예시                                           |
| ----------- | --------------------------------------------------- |
| 목적 고민   | 세럼으로 해결하고 싶은 고민은 무엇인가요?           |
| 최근 자극   | 최근 따가움, 붉어짐, 건조함이 있었나요?             |
| 병행 성분   | 현재 레티놀, 비타민C, AHA/BHA 제품을 사용 중인가요? |
| 사용 시간   | 아침에 사용할 제품인가요, 밤에 사용할 제품인가요?   |
| 기대 시차   | 빠른 효과보다 천천히 안정적인 변화를 원하나요?      |
| 선크림 연계 | 세럼 사용 후 선크림을 꾸준히 바를 수 있나요?        |

##### 립케어

| 체크 항목        | 질문 예시                             |
| ---------------- | ------------------------------------- |
| 갈라짐 정도      | 입술 갈라짐이나 벗겨짐이 반복되나요?  |
| 멘톨 / 화한 느낌 | 화한 립밤을 쓰면 불편한가요?          |
| 향료             | 향이 강한 립 제품이 불편한가요?       |
| 보습 지속력      | 자주 덧바르기 어려운 상황인가요?      |
| SPF 여부         | 야외에서 사용할 립케어가 필요한가요?  |
| 제형             | 스틱, 튜브, 밤 타입 중 선호가 있나요? |

#### Box 3. 판단 결과

> 입력된 조건을 바탕으로 우선순위가 높은 제품 후보와 다음 행동만 보여준다.

판단 결과 박스에서는 복잡한 이유를 길게 설명하지 않고, **상위 제품 N개**와 **CTA 버튼**만 노출한다.

| 결과 요소      | 설명                                      |
| -------------- | ----------------------------------------- |
| 상위 제품 N개  | 현재 조건에 맞는 제품 후보를 3~5개 노출   |
| 제품 기본 정보 | 제품명, 브랜드, 가격대 정도만 간단히 표시 |
| CTA 버튼       | 제품 보러가기                             |

### Feature 3 — Product Matrix

> **선택한 제품군 안에서 제품 후보를 가격대별 Tier List 형태로 비교하는 필터 기반 제품 표**

Product Matrix는 사용자가 선택한 제품군에서 **좋은 제품의 기본 조건**과 **개인화 필터**를 적용한 뒤, 제품 후보를 가격대별로 한 번에 비교할 수 있게 보여준다. 사용자는 필터를 추가·삭제 할 수 있다.

---

#### 화면 구성

```txt
[제품군 Select: 선크림]

좋은 선크림의 조건
[SPF 50 이상] [발림성 우수] [백탁 적음] [눈시림 낮음] [메이크업 궁합] +

개인화 필터
[민감성 피부] [휴대성] [야외 활동] [눈시림 경험] +

----------------------------------------

~2만원
[제품 A  ✓ 적합] [제품 B  △ 주의]

2~5만원
[제품 C  ✓ 적합] [제품 D  ✓ 적합]

5만원+
[제품 E  △ 주의] [제품 F  ✓ 적합]
```

#### 1. 제품군 선택

사용자가 비교할 제품군을 선택한다.

- 선크림
- 세럼
- 립케어
- 로션 / 크림
- 클렌저

---

#### 2. 좋은 제품의 조건 (BASIC_CONDITION)

제품군별로 반드시 확인해야 하는 핵심 기준을 태그 형태로 제공한다.  
관리자가 코드 상수로 정의하며, Product Matrix 진입 시 기본 선택 상태로 시작된다.  
`product_filter_mappings.filter_type = 'BASIC_CONDITION'`으로 구분한다.

**선크림**  
`[SPF 50 이상] [PA++++] [발림성 우수] [눈시림 낮음] [백탁 적음] [메이크업 궁합]`

**세럼**  
`[목적 성분 명확] [자극 가능성 낮음] [병행 주의] [기대 시차]`

**립케어**  
`[보습 지속력] [멘톨 없음] [향료 적음] [SPF 여부] [휴대성]`

---

#### 3. 개인화 필터 (PERSONALIZED)

사용자의 피부 상태와 사용 상황에 따라 제품 후보를 좁히는 필터.  
사용자 답변(user_facts)을 `product_filter_mappings`로 변환해 자동 생성된다.  
`product_filter_mappings.filter_type = 'PERSONALIZED'`으로 구분한다.

`[민감성 피부] [건성] [지성] [휴대성] [메이크업 전 사용] [야외 활동] [향료 회피] [눈시림 경험]`

---

### Feature 4 — 고민 입력 (Intent Entry)

> **"무엇을 사야 할지 모르겠지만, 어떤 문제가 있는지는 알고 있는 사용자"를 위한 진입 인터페이스**

이 Feature는 사용자 세그먼트 중 **B. 고민은 있는데 카테고리를 모름**에 해당한다.

```txt
고민 → Priority Gate / Category Decision → 제품

[헤드라인]
고민부터 시작해도 돼요

[서브텍스트]
어떤 제품이 필요한지 몰라도 괜찮아요.
고민 유형을 고르면 무엇을 먼저 점검해야 하는지부터 정리해드려요.

----------------------------------------

[고민 카테고리 캐러셀]
- 일회성 트러블
- 일상 불편
- 화장 / 꾸미기
- 컴플렉스

----------------------------------------

[각 카테고리별 고민 캐러셀 (무한 스크롤)]
좌 ↔ 우 드래그 / 스와이프 가능
```

#### 고민 카테고리 구조

각 고민은 성격별로 그룹화된다.

1. 일회성 트러블  
   `[뾰루지] [여드름] [붉어짐] [뒤집힘] [트러블 반복] [민감 반응]`
2. 일상 불편  
   `[건조] [당김] [각질] [번들거림] [눈가 건조] [입술 트임]`
3. 화장 / 꾸미기  
   `[화장 뜸] [밀림] [쿠션 추천] [파운데이션 고민] [선크림 추천] [립 제품]`
4. 컴플렉스  
   `[잡티] [다크서클] [홍조] [모공] [피부톤] [탄력]`

우선 태그 형태로 시작해서 사진 + 글자로 확장 가능

### Feature 5 — Reaction Traceback

> **실패 경험을 다음 선택에 반영하는 역추적 도구**

Reaction Traceback은 사용자가 과거에 사용했던 제품 중  
**문제가 있었던 상품**과 **괜찮았던 상품**을 함께 등록하고,  
두 그룹의 성분 차이를 비교해 **원인 후보 성분군**을 추측하는 기능이다.

예시:

```txt
올리브영에서 이 제품을 샀더니 피부가 뒤집어졌어요.
어떤 성분이 문제였을까요?
```

#### 화면 구조

```txt
[문제 상품 등록 +] [괜찮은 상품 등록 +]

Box 1. 등록한 상품
Box 2. 반응 기록
Box 3. 원인 후보
```

#### 1. 상품 등록 방식

상품은 두 가지 방식으로 등록할 수 있다.

**A. 문제 상품 등록**

사용 후 불편하거나 피부 반응이 있었던 제품

등록 방법:

1. 바코드 스캔
2. 브랜드 > 제품군 > 제품 선택
3. 제품명 직접 검색

**B. 괜찮은 상품 등록**

사용해도 큰 문제가 없었거나 잘 맞았던 제품

괜찮은 상품을 함께 등록하는 이유:

문제 상품에 있는 성분이라도 괜찮은 상품에도 공통으로 들어 있다면 원인 후보 우선순위를 낮출 수 있다.

즉, 문제 상품만 보는 것이 아니라 문제 상품과 괜찮은 상품의 차이를 비교한다.

#### Box 3. 원인 후보

문제 상품과 괜찮은 상품의 성분을 비교해 원인 후보를 보여준다.

결과는 확정 원인이 아니라 의심 성분군으로 표현한다.

결과 예시 — 원인 후보로 볼 수 있는 성분군

1. 향료 / fragrance 계열
2. 에센셜오일 계열
3. 멘톨 / 화한 사용감 성분
4. 특정 자외선 차단 필터
5. 고함량 액티브 성분

#### 다음 선택에 반영

Reaction Traceback 결과는 이후 Product Matrix와 Product Detail에 반영된다.

- 각 제품군을 ✓ 필수 / ✕ 제외 / - 무관으로 설정

### Context 관리자 화면

> **사용자에게 어떤 질문을 보여줄지, 그 질문이 어떤 조건에서 노출될지 관리하는 화면**

Context 관리자 화면은 Priority Decision 화면과 비슷하게 **3박스 구조**로 구성한다.

다만 역할은 다르다.

```txt
Priority Gate = 어떤 조건이면 어떤 결론을 낼지 관리
Context       = 어떤 조건이면 어떤 질문을 보여줄지 관리
```

**화면 구조**

- Box 1. Context 질문 목록
- Box 2. 선택한 질문의 Life / 루틴 노출 조건
- Box 3. 선택한 질문의 제품 / 카테고리 노출 조건

---

#### Box 1. Context 질문 목록

사용자에게 보여줄 질문들을 관리한다.

질문들은 화면에 노출되는 순서를 가지며, Drag & Drop으로 순서를 변경할 수 있다.

질문 카드 예시:

```txt
[1] 선크림 사용 여부
    질문: 외출할 때 선크림을 바르나요?
    Key: routine.sunscreen_frequency
    입력 방식: 단일 선택
    상태: ON

[2] 야외 활동 여부
    질문: 하루 기준, 낮에 밖에 있는 시간은 어느 정도인가요?
    Key: life.outdoor_activity
    입력 방식: 단일 선택
    상태: ON

[3] 눈시림 여부
    질문: 선크림을 바르면 눈이 시린 편인가요?
    Key: context.eye_sting
    입력 방식: 예 / 아니오
    상태: ON
```

Box 1에서 질문 하나를 선택하면, Box 2 / Box 3에서 해당 질문이 언제 노출될지 설정한다.

---

#### Box 2. Life / 루틴 노출 조건

선택한 질문이 어떤 Life / 루틴 조건에서 노출될지 설정한다.

예를 들어 눈시림 여부 질문은 모든 사용자에게 물을 필요가 없다.

> 질문: 선크림을 바르면 눈이 시린 편인가요?

Box 2와 Box 3의 각 항목은 3가지 상태로 관리한다.

| 상태   | 의미                                  |
| ------ | ------------------------------------- |
| ✓ 필수 | 이 조건이 맞아야 질문이 노출됨        |
| ✕ 제외 | 이 조건이 맞으면 질문이 노출되지 않음 |
| - 무관 | 이 질문에서는 사용하지 않음           |

---

#### 최종 정리

| 박스  | 역할                                         |
| ----- | -------------------------------------------- |
| Box 1 | 질문 목록과 노출 순서 관리                   |
| Box 2 | 선택한 질문의 Life / 루틴 노출 조건 관리     |
| Box 3 | 선택한 질문의 제품 / 카테고리 노출 조건 관리 |

즉, Context 관리자 화면의 목적은:  
어떤 질문을 / 어떤 사용자에게 / 어떤 제품군에서 / 언제 보여줄지 관리하는 것

---

### Product Filter Mapping 관리 페이지

여기서는 사용자의 구어체 선택값(user_facts)이 제품 attribute 조건으로 어떻게 변환되는지 매핑을 설정한다.  
"룰 엔진"이 아니라 "번역 테이블"이다. 실제 필터링은 product attributes를 기준으로 동적 SQL로 수행한다.

| 사용자 답변 (fact)                    | 변환 조건 (attribute)         | 처리 방식   | 필터 표시 이름 |
| ------------------------------------- | ----------------------------- | ----------- | -------------- |
| context.eye_sting = true              | eye_sting IN ["none","low"]   | HARD_FILTER | 눈시림 낮음    |
| life.outdoor_activity IN [1_3h, over_3h] | spf >= 50                  | HARD_FILTER | 야외 사용 적합 |
| context.white_cast_sensitive = true   | white_cast IN ["none","low"]  | HARD_FILTER | 백탁 없음      |
| preference.fragrance_sensitive = true | fragrance = false             | HARD_FILTER | 향료 없음      |
| context.makeup_use = true             | makeup_compatibility = "good" | TAG         | 메이크업 궁합  |

처리 방식(filter_mode):

| 처리 방식   | 의미                                                      |
| ----------- | --------------------------------------------------------- |
| HARD_FILTER | attribute 조건을 WHERE에 추가해 제품 자체를 조회에서 제외 |
| CAUTION     | 제품은 남기되 △ 주의 태그 표시                            |
| TAG         | 조건 만족 제품에 정보성 태그 부여                         |
| SORT        | 조건 만족 제품을 상위 노출                                |

---

### Product Matrix 필터 자동 생성

Category Decision CTA로 Product Matrix에 진입하면, context 답변과 `product_filter_mappings`를 바탕으로 개인화 필터가 자동으로 선택 상태로 시작된다. Concern preset의 `suggested_filters`가 있다면 최종 category가 일치할 때만 함께 반영된다.

예를 들어 사용자가 이렇게 답했다면:

- 눈시림 있음
- 야외에서 사용
- 메이크업 전 사용
- 민감성 피부

Product Matrix에는 이런 필터가 자동으로 선택된다.

`[눈시림 낮음] [SPF 50 이상] [메이크업 궁합] [향료 주의]`

```txt
Context 답변 → product_filter_mappings → attribute 조건 변환
→ product_matrix_filter_states에 저장 (source: CATEGORY_DECISION_CTA)
→ products 동적 SQL 조회
→ 결과 decision_runs에 snapshot 저장
```

사용자가 필터를 추가/삭제하면 `product_matrix_filter_states.filters`가 업데이트되고, `session_events`에 이벤트로 기록된다.

### Product DB 관리

> **제품 추가, 제품군별 속성, 성분, 가격, 이미지, 구매 링크를 관리하는 화면**

Product DB 관리 화면은 Product Matrix와 Reaction Traceback에서 사용할 제품 데이터를 등록하고 수정하는 화면이다.

**화면 역할**

```txt
제품 기본 정보 등록
→ 제품군 선택
→ 제품군별 Attribute 입력
→ 성분 정보 입력
→ 노출 여부 관리
```

#### 관리 항목

| 항목          | 설명                                      |
| ------------- | ----------------------------------------- |
| 브랜드        | 제품 브랜드                               |
| 제품명        | 상품명                                    |
| 제품군        | 스킨/토너, 선크림, 에센스/세럼/앰플, 립케어, 로션,크림, 클렌저 |
| 가격          | 제품 가격                                 |
| 가격대        | ~2만원 / 2~5만원 / 5만원+                 |
| 용량          | ml / g                                    |
| 이미지        | 제품 이미지                               |
| 구매 링크     | 올리브영 / 브랜드몰 / 기타 링크           |
| 성분표        | 전성분 정보                               |
| 제품군별 속성 | SPF, PA, 눈시림, 멘톨 여부 등             |
| 노출 여부     | Product Matrix 노출 / 비노출              |

#### 제품군별 Attribute

**선크림**

- SPF
- PA
- 필터 타입
- 눈시림 정도
- 백탁 정도
- 발림성
- 끈적임
- 메이크업 궁합
- 휴대성

**세럼**

- 목적 성분
- 자극 가능성
- 병행 주의 성분
- 사용 시간대
- 기대 시차
- 제형

**립케어**

- 멘톨 여부
- 향료 여부
- SPF 여부
- 보습 지속력
- 제형
- 휴대성

#### 상품 등록 방식

1. 브랜드 선택
2. 제품군 선택
3. 제품명 입력
4. 가격 / 용량 / 이미지 입력
5. 제품군별 Attribute 입력
6. 성분표 입력
7. 구매 링크 입력
8. 노출 여부 설정

> Product DB 관리는 단순 상품 등록 화면이 아니다. 제품군별 attributes와 성분 데이터를 함께 관리해서 Product Matrix, Product Filter Mapping, Reaction Traceback에서 사용할 수 있게 만든다. attributes를 얼마나 정확하게 입력하느냐가 필터링 품질을 결정한다.

## 사용자 세그먼트별 흐름

### A. 어디서부터 손댈지 모름

> 루틴이 불안정하거나, 무엇을 사야 할지 기준 자체가 없는 사용자

```
S01 → S02 (Priority Gate) → S03 → S04 → S05 → S06 → S07 → S08 (Tracker)
```

Priority Gate를 거쳐 지금 제품을 사야 하는 상태인지 먼저 판단한 뒤, Category Decision을 순서대로 거쳐 제품을 고른다. 이후 S08에서 루틴 추적을 시작할 수 있다.

---

### B. 고민은 있는데 카테고리를 모름

> 어떤 제품군이 필요한지 모르지만, 해결하고 싶은 피부 문제가 있는 사용자

```
S01 → S02 (Priority Gate) → S03 → S04 → S05 → S06 → S07
```

고민 유형을 선택하면 concern preset이 먼저 저장되고, 기본적으로 Priority Gate를 거쳐 루틴 안정 여부를 먼저 판단한다. 이후 Category Decision → Product Matrix 순서로 진행한다. 입술 트임, 선크림 추천, 립 제품, 메이크업 궁합 계열처럼 제품군이 비교적 명확한 일부 고민은 Category Decision부터 시작할 수 있다.

---

### C. 이미 찾는 제품군이 있음 (Fast Lane)

> 선크림, 세럼 등 원하는 카테고리가 이미 정해진 사용자

```
S01 → 제품군 칩 선택 → S03 → S04 → S05 → S06 → S07
```

Landing에서 제품군 칩을 바로 선택해 Priority Gate를 건너뛰고 Category Decision부터 시작한다. 탐색 흐름을 단축해 빠르게 제품 후보에 도달할 수 있다.

---

### D. 실패 원인 추적형

> 과거에 사용한 제품에서 피부 반응이 있었고, 원인 성분을 파악하고 싶은 사용자

```
S01 → S02 (Priority Gate) → S08 (Traceback) → S06
```

Priority Gate를 거쳐 현재 루틴 안정 여부를 확인한 뒤, Reaction Traceback에서 문제 상품과 괜찮은 상품을 비교 등록한다. 원인 후보 성분이 도출되면 Product Matrix에 필터로 반영된다.
