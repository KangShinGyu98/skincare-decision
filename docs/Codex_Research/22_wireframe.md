# 22 Wireframe: 화면 구조 및 세그먼트별 유저 저니
*Wireframe | Codex | 2026-04-25*

---

## 화면 목록

### 1. 랜딩 페이지

**역할**
서비스 진입점. 무엇을 해주는 서비스인지 설명하고 사용자가 자신의 상황을 선택하도록 유도.

**최종 산출물**
세그먼트 선택 → 해당 흐름으로 분기

**구성 요소**
- 서비스 한 줄 설명
- 고민 예시 3~4개 (실제 사용자 언어)
- 세그먼트 선택 CTA 4개
  - 어디서부터 손댈지 모르겠어요
  - 고민은 있는데 어떤 제품인지 모르겠어요
  - 이미 찾는 제품군이 있어요
  - 안 맞았던 제품 원인을 알고 싶어요

---

### 2. Priority Gate

**역할**
지금 제품이 실제로 필요한 상황인지 확인. 현재 루틴 공백을 찾아내고, 생활/자극 요인이 먼저인 경우 걸러냄.

**최종 산출물**
- 루틴 공백 있음 → 해당 카테고리 먼저 권고
- 상황 체크 多 → 루틴/생활 정비 먼저 안내 + 보류 옵션
- 피부과 고려 → 외부 연결 또는 보류
- 이상 없음 → Minimal Context로 진행

**구성 요소**

Part A. 현재 루틴 제품 체크 (우선순위 순서)

| 제품군 | 선택 |
|---|---|
| 클렌저 | 매일 씀 / 가끔 씀 / 안 씀 |
| 토너 / 스킨 | 매일 씀 / 가끔 씀 / 안 씀 |
| 로션 / 크림 | 매일 씀 / 가끔 씀 / 안 씀 |
| 썬크림 | 매일 씀 / 가끔 씀 / 안 씀 |
| 세럼 / 앰플 | 매일 씀 / 가끔 씀 / 안 씀 |

결과 로직
- 클렌저~썬크림 중 "안 씀" 항목 있음 → 해당 제품군 먼저 채우도록 권고
- 전 항목 안정 → 세럼/앰플 등 기능성 탐색 진행

Part B. 상황 체크 (해당 / 비해당)
- 세안 후 당김/자극이 자주 있다
- 최근 강한 액티브/필링/홈케어를 했다
- 최근 여러 화장품을 한꺼번에 바꿨다
- 같은 문제가 2~4주 이상 반복된다
- 최근 수면/스트레스/식습관 변화가 크다
- 이 문제로 상담이 필요하다고 느낀다

결과 판단 기준 (Part B 기준)
- 0~1개: 탐색 진행
- 2~3개: 루틴 점검 권고 + 계속 진행 선택 가능
- 4개 이상: 루틴/생활 먼저 강권 + 피부과 고려 안내

> 조건부 문항 없음. 제품 관련 조건은 Part A가 대체하고, 카테고리별 세부 질문은 Minimal Context에서 다룸.

---

### 3. Minimal Context

**역할**
선택된 카테고리 기준으로 개인화 필터를 구성. 제품군마다 질문이 다름.

**최종 산출물**
개인화 필터 세트 → Product Screener에 적용

**구성 요소**

공통 질문 (카테고리 무관)
- 민감도 (민감 / 보통 / 강함)
- 예산대 (1만 이하 / 1~3만 / 3만 이상)

카테고리별 질문

| 카테고리 | 추가 질문 |
|---|---|
| 스킨/로션/세럼 | 피부타입, 제형 선호 (수분/오일/젤) |
| 썬크림 | 미백 선호 여부, 휴대용 vs 집용, 백탁 민감도 |
| 립밤 | 촉촉함 vs 가벼움, 틴트 여부 |
| 클렌저 | 세정력 선호, 오일/폼/젤 선호 |
| 파운데이션/쿠션 | 커버력, 피부결, 지속력 vs 촉촉함 |
| 스팟/트러블 케어 | 현재 트러블 상태, 액티브 사용 여부 |

---

### 4. Product Screener

**역할**
필터링된 제품을 가격대별 Grid로 보여주고 사용자가 직접 선택하는 화면. 선택 기준도 함께 제공.

**최종 산출물**
제품 선택 또는 비교 진입

**구성 요소**
- 상단: Priority/Context 필터 요약 배지
- 좌측 또는 상단 블록: 카테고리별 선택 기준 (좋은 제품이란? / 피해야 할 것은?)
- 메인: 가격대별 제품 Grid
  - 1만 이하 / 1~3만 / 3만 이상 구간
  - 제품 카드: 이름, 브랜드, 가격, 적합도 태그, 주의 태그
- 하단: 선택한 제품 비교 / 상세 보기 / 지금은 보류

---

### 5. 문제 원인 찾기

**역할**
기존에 안 맞았던 제품/루틴의 원인을 역추적. 회피 성분/제형 규칙을 도출.

**최종 산출물**
회피 규칙 생성 → Product Screener 필터에 반영 가능

**구성 요소**
- 안 맞았던 제품 입력 (검색 또는 직접 입력)
- 당시 증상 선택 (따가움 / 트러블 / 밀림 / 건조 / 기타)
- 당시 루틴 상태 확인 (다른 액티브 병행 여부, 세정 빈도 등)
- 의심 원인 후보 도출
- 회피 규칙 저장 + Product Screener 연결 CTA

---

### 6. Concern Mapper

**역할**
고민은 있지만 제품군을 모르는 사용자가 고민 유형을 선택하면 제품 카테고리로 매핑.

**최종 산출물**
카테고리 preset → Priority Gate 또는 Minimal Context로 분기

**구성 요소**
- 4개 고민 유형 타일
  - 일회성 트러블 (여드름, 블랙헤드, 뾰루지)
  - 일상 불편 (속건조, 입술틈, 각질)
  - 화장/꾸미기 (파데찾기, 쿠션 추천)
  - 컴플렉스 (주근깨, 모공, 칙칙함)
- 각 타일 선택 시 세부 concern 리스트 펼침
- 검색 입력창 (자유 입력 가능)
- 컴플렉스 선택 시 disambiguation 1문항: "치료/개선할건지 vs 가릴건지"
- 선택 완료 후 카테고리 preset 표시 + 다음 단계 CTA

## 세그먼트별 유저 저니

### A. 어디서부터 손댈지 모름

```
랜딩
  └─ "어디서부터 손댈지 모르겠어요" 선택
       └─ Priority Gate
            ├─ 루틴 문제 감지 → 루틴 먼저 안내 + 보류
            └─ 제품 탐색 진행
                 └─ Minimal Context (카테고리는 Gate 결과에서 권고)
                      └─ Product Screener
```

---

### B. 고민은 있는데 카테고리를 모름

```
랜딩
  └─ "고민은 있는데 어떤 제품인지 모르겠어요" 선택
       └─ Concern Mapper
            ├─ 일회성 트러블 / 일상 불편
            │    └─ 카테고리 preset
            │         └─ Priority Gate
            │              └─ Minimal Context
            │                   └─ Product Screener
            │
            ├─ 화장/꾸미기
            │    └─ 카테고리 preset
            │         └─ Minimal Context (Priority Gate 스킵 또는 1문항)
            │              └─ Product Screener
            │
            └─ 컴플렉스
                 └─ disambiguation: 치료 vs 커버
                      ├─ 치료/개선 → 스킨케어 카테고리 preset → Priority Gate → Minimal Context → Product Screener
                      └─ 커버 → 메이크업 카테고리 preset → Minimal Context → Product Screener
```

---

### C. 이미 찾는 제품군이 있음

```
랜딩
  └─ "이미 찾는 제품군이 있어요" 선택
       └─ 카테고리 직접 선택 (preset 타일)
            └─ Minimal Context
                 └─ Product Screener
```

Priority Gate는 선택 사항으로 제공 ("정말 지금 필요한지 먼저 확인하고 싶어요" 옵션).

---

### D. 안 맞았던 제품 원인을 알고 싶음

```
랜딩
  └─ "안 맞았던 제품 원인을 알고 싶어요" 선택
       └─ 문제 원인 찾기
            └─ 회피 규칙 도출
                 └─ (선택) Product Screener로 연결 → 회피 필터 적용된 상태로 진입
```
