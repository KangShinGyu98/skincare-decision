# 19 Wireframe: 화면 구성 및 컴포넌트 정의

_Wireframe planning document | Codex | 2026-04-22_

---

## 1. 문서 목적

이 문서는 `21_decision_flow_revision.md` 기준으로  
**Skincare Decision MVP의 수정된 화면 구조와 화면별 핵심 컴포넌트**를 정리한 와이어프레임 문서다.

이번 수정의 핵심은 아래 4가지다.

1. **특정 제품군 intent 사용자를 위한 fast lane 추가**
2. **Priority Gate가 Skin Profile보다 먼저 오는 구조**
3. **Skin Profile은 Minimal Context로 축소**
4. **Category Decision + Product Compare를 Category Decision Matrix로 통합**

즉, 이 문서는 기존 19번의 `v2`에 가깝다.

---

## 2. 화면 수 결론

### MVP 기준

**코어 화면 8개**가 적절하다.

1. 랜딩 / Intent Entry
2. 진입 분기 / 세그먼트 선택
3. Priority Gate
4. Minimal Context 입력
5. Decision Result
6. Category Decision Matrix
7. Product Fit Detail
8. Reaction Traceback / Adaptation Tracker

### 선택 화면

운영 편의와 재방문을 위해 아래 **보조 화면 3개**를 붙일 수 있다.

9. 로그인 / 저장 유도
10. 내 기록 보기
11. 공유 가능한 결과 페이지

### 실무 기준 결론

- **MVP 라우트 수:** 8개
- **v1 라우트 수:** 11개 내외
- **피그마 프레임 수:** 상태값까지 포함하면 24~32개
- **프론트엔드 재사용 컴포넌트:** 13~17개

즉, 화면 수는 줄었지만 실제 밀도는 더 높아진 구조다.

---

## 3. 전체 흐름

```text
S01 랜딩 / Intent Entry
 -> S02 진입 분기 / 세그먼트 선택
    -> A 어디서부터 손댈지 모름
       -> S03 Priority Gate
       -> S04 Minimal Context
       -> S05 Decision Result
       -> S06 Category Decision Matrix
       -> S07 Product Fit Detail
       -> S08 Adaptation Tracker

    -> B 고민은 있는데 카테고리를 모름
       -> S03 Priority Gate
       -> S04 Minimal Context
       -> S05 Decision Result
       -> S06 Category Decision Matrix
       -> S07 Product Fit Detail

    -> C 이미 찾는 제품군이 있음
       -> 카테고리 preset
       -> S03 Priority Gate
       -> S04 Minimal Context
       -> S05 Decision Result
       -> S06 Category Decision Matrix
       -> S07 Product Fit Detail

    -> D 예전에 안 맞았던 제품 원인을 알고 싶음
       -> S08 Reaction Traceback
```

핵심은 아래 순서다.

> **필요성 점검 -> 맥락 보정 -> 선택 기준 제시 -> 필터링된 제품 비교 -> 사용 후 학습**

## 4. 화면별 정의

## S01. 랜딩 / Intent Entry

### 역할

검색/콘텐츠 유입 직후 사용자가  
`이 서비스가 뭘 해결해주는지`, `어떤 입구로 들어가야 하는지`, `특정 제품군으로 바로 들어갈 수 있는지`를 이해하는 화면이다.

### 핵심 컴포넌트

1. **Hero headline**
2. **한 문장 가치 제안**
3. **대표 고민 예시 칩**
4. **직접 진입 CTA 묶음**
5. **제품군 fast lane 칩**
6. **샘플 결과 미리보기 카드**
7. **법적/의료 비진단 안내 배너**

### 권장 CTA

- `내 상황부터 정리하기`
- `이미 찾는 제품군이 있어요`
- `안 맞았던 제품 원인 추적하기`

### Fast lane 예시

- 선크림
- 세럼
- 장벽 크림
- 클렌저
- 립 케어
- 토너패드

### 화면 메모

- 첫 화면에서 긴 제품 리스트를 보여줄 필요는 없다.
- 대신 검색 유입 사용자가 `바로 들어갈 길`이 있다는 것을 보여줘야 한다.

---

## S02. 진입 분기 / 세그먼트 선택

### 역할

사용자를 복잡한 설문으로 보내기 전에  
현재 의사결정 상태를 4개 중 하나로 분기시키는 화면이다.

### 핵심 컴포넌트

1. **세그먼트 선택 카드 4종**
2. **각 세그먼트 설명 한 줄**
3. **대표 예시 문장**
4. **progress header**
5. **도움말 링크 또는 FAQ 토글**

### 세그먼트 버튼

1. 어디서부터 손대야 할지 모르겠어요
2. 고민은 있는데 어떤 카테고리인지 모르겠어요
3. 이미 찾는 제품군이 있어요
4. 예전에 안 맞았던 제품 원인을 알고 싶어요

### 화면 메모

- 로그인보다 먼저 나와야 한다.
- 3번 세그먼트는 `카테고리 preset`과 바로 연결되어야 한다.

---

## S03. Priority Gate

### 역할

이 서비스의 첫 핵심 판단 화면이다.  
사용자에게 `지금 제품이 필요한가`, `루틴/생활/자극 요인이 먼저인가`, `상담 고려가 필요한가`를 먼저 점검하게 한다.

### 핵심 컴포넌트

1. **공통 Priority Checklist**
2. **조건부 Priority 질문 블록**
3. **카테고리 preset 요약 바**
4. **즉시 피드백 배너**
5. **보류/주의 메시지 박스**
6. **다음 단계 CTA**

### 공통 Priority 문항 예시

- 최근 기본 보습/보호 루틴이 불안정하다
- 세안 후 당김/자극이 자주 있다
- 최근 강한 액티브/필링/홈케어를 했다
- 최근 여러 화장품을 한꺼번에 바꿨다
- 같은 문제가 2~4주 이상 반복된다
- 최근 수면/스트레스/식습관 변화가 크다
- 이 문제로 일상 스트레스가 크거나 상담이 필요하다고 느낀다

### 조건부 문항 예시

선케어 관심:

- 매일 선크림을 바르고 있다
- 외출 시 재도포가 가능하다

메이크업 밀림:

- 아침 루틴이 너무 무겁지 않다
- 스킨케어 후 바로 화장을 하지 않는다

트러블:

- 최근 강한 패드/필링/레티노이드 사용이 과하지 않았다

### 화면 메모

- 이 화면은 설문이 아니라 `gate`여야 한다.
- 사용자는 여기서 이미 "지금 사지 말아야 할 것"을 일부 이해해야 한다.

---

## S04. Minimal Context 입력

### 역할

Priority Gate 이후에만 필요한 최소 맥락을 받아  
후보를 줄이는 화면이다.

### 핵심 컴포넌트

1. **민감도 선택 칩**
2. **현재 사용 중 액티브 선택 모듈**
3. **피부 타입 또는 현재 피부 상태 선택 칩**
4. **제형 선호 칩**
5. **예산대 세그먼트**
6. **선택적 문제 부위/상황 입력**
7. **건너뛰기 / 잘 모르겠어요 버튼**

### 입력 항목

- 민감도
- 현재 사용 중 액티브
- 피부 타입 또는 자기 인식 피부 상태
- 제형 선호
- 예산대
- 필요 시 사용 상황

### 화면 메모

- 이 화면은 `Skin Profile`보다 훨씬 가볍게 가야 한다.
- 초기 개인화의 목적은 정교한 추천이 아니라 `후보 축소`다.

---

## S05. Decision Result

### 역할

사용자에게 `지금 제일 먼저 해야 할 것`, `지금 보류할 것`, `봐야 할 카테고리`, `다음 행동`을 동시에 보여주는 허브 화면이다.

### 핵심 컴포넌트

1. **Top Priority Card**
2. **보류/주의 Card**
3. **왜 이런 결론이 나왔는지 설명 블록**
4. **추천 카테고리 블록**
5. **다음 액션 CTA 묶음**
6. **상담 고려 또는 경고 배너**
7. **간단한 Action Plan 요약**

### 결과 예시

- 지금 최우선: 선크림 정착
- 지금 보류: 미백 세럼 추가
- 지금 볼 카테고리: 데일리 선크림
- 이유: 현재 자외선 관리가 불안정하고, 액티브 추가보다 루틴 안정화가 먼저

### 권장 CTA

- `이 카테고리 자세히 보기`
- `가격대별 후보 보기`
- `실패 기록 반영하기`

### 화면 메모

- 이 화면의 설득력이 MVP 성패를 좌우한다.
- "추천"보다 "왜 이건 아직 아닌지"의 설명이 더 중요하다.

---

## S06. Category Decision Matrix

### 역할

기존 `Category Decision`과 `Product Compare`를 합친 화면이다.  
사용자가 `무엇을 봐야 하는지`와 `무엇을 고를 수 있는지`를 동시에 이해하게 한다.

### 핵심 컴포넌트

1. **현재 문제 / Priority 요약 바**
2. **카테고리 헤더**
3. **카테고리 핵심 판단축 블록**
4. **Good fit / Skip if 비교 블록**
5. **제형/사용감 기준 칩**
6. **가격대 선택 바**
7. **필터링된 Product Matrix**
8. **적합도/주의 태그**
9. **비교 추가 컨트롤**
10. **Product Fit Detail 진입 CTA**

### 카테고리별 예시 모듈

- 선크림: SPF/PA, 백탁, 눈시림, 재도포 편의, 메이크업 궁합
- 세럼: 목적 성분, 병행 주의, 기대 시차, 자극 가능성
- 립케어: 보호막, 향료 여부, 휴대성, SPF 여부

### Product Matrix 기준 예시

- 가격대별 라인
- 사용감/제형별 라인
- 민감도 적합성
- 자극 주의 태그
- 회피 성분/제형 태그

### 화면 메모

- 이 화면이야말로 이 서비스의 실질적인 `탐색 코어`다.
- 기존 커머스처럼 제품만 먼저 보이지 않게 해야 한다.

---

## S07. Product Fit Detail

### 역할

특정 제품 하나에 대해  
`누구에게 맞고 누구에게는 왜 애매한지`를 설명하는 상세 화면이다.

### 핵심 컴포넌트

1. **Product Fit Hero Card**
2. **적합 / 주의 / 회피 요약 블록**
3. **이유 설명 아코디언**
4. **Similar-Skin Evidence 블록**
5. **핵심 성분 요약 카드**
6. **사용 순서 / 빈도 가이드**
7. **흔한 실패 이유 블록**
8. **대안 제품 스트립**
9. **사용 후 기록 CTA**
10. **구매 링크 분리 영역**

### 화면 메모

- 상세 화면은 후기 나열보다 요약 구조가 먼저 나와야 한다.
- 구매 링크가 있다면 판단 영역과 시각적으로 분리해야 한다.

---

## S08. Reaction Traceback / Adaptation Tracker

### 역할

이 화면은 두 개의 서브플로우를 가진다.

- **Traceback 탭:** 예전에 안 맞았던 제품의 공통 의심군 추출
- **Tracker 탭:** 새로 쓴 제품의 Day 3 / 7 / 21 반응 기록

### 핵심 컴포넌트

1. **탭 스위처**
2. **제품 검색 / 바코드 / QR 입력 모듈**
3. **증상 선택 칩**
4. **부위 선택 바디 맵 또는 부위 칩**
5. **발현 시점 선택기**
6. **의심군 결과 카드**
7. **회피 규칙 생성 카드**
8. **피부과 / patch testing 안내 배너**
9. **Day 3 / 7 / 21 체크인 카드**
10. **기록 저장 CTA**

### Traceback 결과 예시

- 의심군: 향료군 / 에센셜오일군 / leave-on 바디 제품군
- 확정 불가: 단일 성분 알레르기 확정 아님
- 다음 추천 규칙: 해당 군 우선 회피

### 화면 메모

- `원인 확정`이 아니라 `원인 후보` 언어를 사용해야 한다.
- D세그먼트 사용자는 여기서 바로 시작할 수 있어야 한다.

## 7. 구현 정밀도 기준

### 디자인 기준

로우파이 와이어프레임은 8~11화면이지만, 실제 설계에서는 아래 상태를 같이 잡아야 한다.

- 기본 상태
- 선택 상태
- 로딩 상태
- 결과 없음 상태
- 입력 누락 상태
- 경고/상담 안내 노출 상태
- Priority Gate 보류 상태

따라서 실제 피그마 프레임은 **최소 24개 이상**으로 보는 것이 안전하다.

### 프론트엔드 기준

개발 단위로 보면 다음 정도가 현실적이다.

- **페이지 컴포넌트:** 8~11개
- **재사용 컴포넌트:** 13~17개
- **화면 전용 모듈:** 6~9개
- **총 UI 단위:** 23~28개

즉, 작아 보이지만 3~4페이지짜리 단순 서비스는 아니다.

## 8. 우선 제작 순서

### Phase 1

반드시 먼저 그릴 화면:

1. S01 랜딩 / Intent Entry
2. S02 진입 분기
3. S03 Priority Gate
4. S04 Minimal Context
5. S05 Decision Result

이 5개만 있어도 제품의 핵심 가치 검증이 가능하다.

### Phase 2

다음으로 붙일 화면:

6. S06 Category Decision Matrix
7. S07 Product Fit Detail

이 단계부터 비로소 `추천까지 되는 서비스`가 된다.

### Phase 3

차별화 강화를 위한 화면:

8. S08 Reaction Traceback / Adaptation Tracker

이 화면이 들어가면 서비스는 단순 추천 툴이 아니라  
`실패 학습이 가능한 의사결정 플랫폼`으로 바뀐다.

---

## 9. 최종 권장안

가장 현실적인 설계는 아래와 같다.

- **MVP는 8개 코어 화면**
- **핵심은 S03 Priority Gate + S05 Decision Result**
- **탐색 핵심은 S06 Category Decision Matrix**
- **특정 제품군 intent 사용자를 위한 fast lane을 반드시 제공**
- **커머스 링크는 Product Fit 판단과 시각적으로 분리**
- **Traceback은 확률적/보조적 언어를 사용**

한 문장으로 정리하면,  
**이 서비스의 와이어프레임은 "예쁜 제품 리스트"를 만드는 작업이 아니라 "필요성 점검 -> 맥락 보정 -> 선택 기준 제시 -> 필터링된 Product Matrix -> 사용 후 학습" 흐름을 설계하는 작업이다.**
