## 2. 식약처 화장품 원료성분정보 OpenAPI

### 2.1 기본 정보

- **출처 페이지**: https://www.data.go.kr/data/15111774/openapi.do
- **제공기관**: 식품의약품안전처
- **사용 비용**: 무료 (공공데이터포털 활용신청 필요)
- **호출 한도**: 활용신청 단계에서 일/월 한도 협의 (보통 일 10,000회 이상)
- **갱신 주기**: 월 또는 분기

### 2.2 인증 / 등록

1. data.go.kr 회원가입.
2. 해당 OpenAPI 페이지에서 "활용신청" → 사용 목적 입력 → 자동/수동 승인.
3. 발급된 인증키(`serviceKey`)를 쿼리 파라미터로 전달.

### 2.3 가져올 수 있는 필드

| 필드              | 설명                                |
| ----------------- | ----------------------------------- |
| 원료성분명 (한글) | 식약처 표준 한글명                  |
| 원료성분명 (영문) | INCI 또는 영문명                    |
| 원료성분 분류     | (예: 보존제, 자외선차단제, 색소 등) |
| 사용 제한 정보    | 금지/제한 농도, 제형 한정           |
| 검토일 / 갱신일   | 식약처 갱신 이력                    |

> ⚠️ 정확한 응답 필드명은 활용신청 후 받는 명세서에서 확인 필요. 본 표는 페이지 설명 기반 추정.

### 2.4 우리 product 필드와의 매핑

| 우리 필드               | 식약처 필드      | 변환 규칙              |
| ----------------------- | ---------------- | ---------------------- |
| `ingredients.name_ko`   | 원료성분명(한글) | 그대로                 |
| `ingredients.name_en`   | 원료성분명(영문) | 그대로                 |
| `ingredients.inci_name` | 원료성분명(영문) | INCI 표준 매핑 후 저장 |

### 2.5 한계 / 약관

- 제품 단위 정보 없음 — **성분 마스터 시드만 가능**.
- 사용 제한 정보는 매월 갱신될 수 있어 정기 동기화 필요.

### 2.6 권장 활용

- **조합 Z 시 사용**: `ingredients` 테이블 일괄 시드(약 5,000~10,000건 추정).
- 분기별 CSV/Excel 일괄 다운로드 → 자체 마이그레이션 스크립트로 upsert.

## 3. 식약처 기능성화장품 보고품목정보 OpenAPI

### 3.1 기본 정보

- **출처 페이지**: https://www.data.go.kr/data/15095680/openapi.do
- **제공기관**: 식품의약품안전처
- **사용 비용**: 무료
- **호출 한도**: 활용신청 단계 협의
- **갱신 주기**: 매일 ~ 주간 (보고 등록에 따라)

### 3.2 가져올 수 있는 필드

| 필드               | 설명                                                     |
| ------------------ | -------------------------------------------------------- |
| 품목명             | 화장품 정식 품목명                                       |
| 제조판매업자       | 회사명                                                   |
| 제조판매업등록번호 | 식약처 등록번호                                          |
| 보고일련번호       | 식약처 보고번호 (검증 키)                                |
| 보고일             | 보고 등록일                                              |
| 효능·효과          | 미백 / 주름개선 / 자외선차단 등 (식약처 인정 11개 중 1+) |
| 사용 시 주의사항   | 라벨에 표기되는 주의사항 텍스트                          |

### 3.3 우리 product 필드와의 매핑

| 우리 필드  | 식약처 필드        | 변환 규칙                           |
| ---------- | ------------------ | ----------------------------------- |
| `name`     | 품목명             | 그대로                              |
| `brand_id` | 제조판매업자       | brands 테이블 자동완성/신규 등록    |
| (없음)     | 제조판매업등록번호 | `attributes._mfds_register_no` 메모 |
| (없음)     | 보고일련번호       | `attributes._mfds_report_no` 메모   |
| (라벨)     | 효능·효과          | sunscreen 카테고리 검증 등에 사용   |
| (라벨)     | 사용 시 주의사항   | Product Detail 화면에 노출 가능     |

### 3.4 한계 / 약관

- **가격, 이미지, 전성분 없음**.
- 기능성 인정 제품만 등록 — 비기능성(예: 일반 보습제)은 검색 안됨.
- 동일 제품 다중 보고(시리즈/리뉴얼)로 인한 중복 row 가능.

### 3.5 권장 활용

- **조합 Y/Z 시 사용**: 관리자가 입력한 `name`을 키로 보고품목 DB 조회 → 효능·효과·주의사항 라벨 자동 채움.
- 검증 용도: "이 제품이 식약처에 미백 기능성으로 보고됐는가?"를 확인.

## 4. Naver 쇼핑 검색 API

### 4.1 기본 정보

- **출처 페이지**: https://developers.naver.com/docs/serviceapi/search/shopping/shopping.md
- **제공기관**: NAVER (네이버)
- **사용 비용**: 무료
- **호출 한도**: 25,000회/일 (검색 API 공통 기본)
- **인증**: 애플리케이션 등록 후 Client ID + Client Secret

### 4.2 인증 / 등록

1. https://developers.naver.com 회원가입 + 애플리케이션 등록.
2. 사용 API: "검색 — 쇼핑" 체크.
3. Client ID / Client Secret 발급.
4. 호출 시 헤더에 두 값 첨부:
   ```
   X-Naver-Client-Id: <CLIENT_ID>
   X-Naver-Client-Secret: <CLIENT_SECRET>
   ```

### 4.3 요청 예시

```
GET https://openapi.naver.com/v1/search/shop.json?query=자작나무선크림&display=10&start=1&sort=sim
```

| 파라미터  | 설명              | 기본값 / 범위                                                              |
| --------- | ----------------- | -------------------------------------------------------------------------- |
| `query`   | 검색어 (UTF-8)    | 필수                                                                       |
| `display` | 한 페이지 결과 수 | 10 (1~100)                                                                 |
| `start`   | 시작 위치         | 1 (1~1000)                                                                 |
| `sort`    | 정렬              | `sim`(정확도) / `date`(날짜) / `asc`(가격 오름차순) / `dsc`(가격 내림차순) |

### 4.4 응답 예시

```json
{
  "lastBuildDate": "Sat, 02 May 2026 12:00:00 +0900",
  "total": 245,
  "start": 1,
  "display": 10,
  "items": [
    {
      "title": "라운드랩 자작나무 수분 <b>선크림</b> 50ml",
      "link": "https://search.shopping.naver.com/...",
      "image": "https://shopping-phinf.pstatic.net/main_8261234/82612345678.jpg",
      "lprice": "16800",
      "hprice": "0",
      "mallName": "스마트스토어",
      "productId": "82612345678",
      "productType": "1",
      "brand": "라운드랩",
      "maker": "라운드랩",
      "category1": "화장품/미용",
      "category2": "선케어",
      "category3": "선크림",
      "category4": ""
    }
  ]
}
```

### 4.5 응답 필드 상세

| 필드          | 타입   | 설명                                                 |
| ------------- | ------ | ---------------------------------------------------- |
| `title`       | string | 제품명 (HTML `<b>` 태그 포함 — 클라이언트에서 strip) |
| `link`        | string | 네이버 쇼핑 검색 결과 페이지                         |
| `image`       | string | 썸네일 이미지 URL (Naver/판매자 서버)                |
| `lprice`      | string | 최저가 (정수형 문자열)                               |
| `hprice`      | string | 최고가 ("0"이면 단일 판매처)                         |
| `mallName`    | string | 판매처 이름                                          |
| `productId`   | string | Naver 내부 ID                                        |
| `productType` | string | 1: 일반 / 2: 가격비교 / 3: 단독 등                   |
| `brand`       | string | 브랜드명 (없으면 빈 문자열)                          |
| `maker`       | string | 제조사 (보통 brand와 동일)                           |
| `category1~4` | string | 네이버 카테고리 트리                                 |

### 4.6 우리 product 필드와의 매핑

| 우리 필드                      | Naver 필드          | 변환 규칙                                   |
| ------------------------------ | ------------------- | ------------------------------------------- |
| `name`                         | `items[].title`     | `<b></b>` strip + 용량 표기 분리 권장       |
| `brand`                        | `items[].brand`     | `brands` 테이블 자동완성/신규               |
| `price`                        | `items[].lprice`    | `parseInt`                                  |
| `price_band`                   | (자동 계산)         | price 기반                                  |
| `image_url`                    | `items[].image`     | **S3 다운로드 후 사용** (hot-link 금지)     |
| `purchase_url`                 | `items[].link`      | 그대로                                      |
| `attributes._naver_product_id` | `items[].productId` | 외부 식별자 메모                            |
| `category`                     | (직접 매핑)         | category3 → 우리 6개 중 매핑 (sunscreen 등) |

### 4.7 한계 / 약관

- **전성분 정보 없음**.
- 이미지 URL은 변경/차단될 수 있음 → S3 다운로드가 안전.
- 검색 결과 정렬은 Naver 알고리즘 (정확도/광고 영향) — 1순위가 항상 정답이 아님.
- 약관: 검색 결과 정보를 자체 서비스에 노출하는 것은 가능. 단, **이미지 hot-link는 약관과 무관하게 운영 위험**(URL 변경, hotlink 차단).
- 어필리에이트 링크 자동 생성 안됨 → 별도 Naver 쇼핑 파트너스 가입 필요.

### 4.8 권장 활용

- **조합 Y/Z 시 사용**: 관리자가 제품명 입력 시 Naver 검색 결과 5건을 후보로 노출 → 운영자가 1건 선택 → 가격/이미지/구매URL 자동 채움 → 이미지는 S3 다운로드.

## 6. AIHub 화장품 패키징 OCR 데이터셋

### 6.1 기본 정보

- **출처**: https://aihub.or.kr/aihubdata/data/view.do?dataSetSn=633
- **제공기관**: 한국지능정보사회진흥원 (NIA)
- **사용 비용**: 무료 (회원가입 + 활용계약 필요)
- **데이터 규모**: 수만 장의 화장품 라벨 이미지 + OCR ground-truth

### 6.2 가져올 수 있는 정보

- 화장품 라벨 이미지 (전면/후면)
- 텍스트 영역 좌표 + OCR 텍스트
- **전성분 텍스트 ground-truth** (라벨에서 추출)

### 6.3 권장 활용

- **Phase 6+ 자동화**: 자체 전성분 OCR 모델 학습 → 관리자가 라벨 사진 업로드 → 자동 추출 → 검토.
- MVP 단계에서는 활용 보류 (사람 시간 vs 모델 학습 ROI 검토 필요).
