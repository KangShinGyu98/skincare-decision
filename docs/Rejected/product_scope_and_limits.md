# Skincare Decision MVP — 제품 범위 / 한계 문서

> 목적: 이 서비스가 **지금 실제로 어디까지 도와줄 수 있는지**, 그리고 **어디부터는 아직 자동화하지 않고 큐레이터 책임으로 남겨두는지**를 명확히 한다.  
> 기준 문서: [skincare_product_selection_rule.md](skincare_product_selection_rule.md), [skincare_rules_from_articles.md](../crawl/skincare_rules_from_articles.md)  
> 작성일: 2026-05-04

## 0. 이 문서의 핵심

이 서비스는 스킨케어 제품을 고를 때 흔히 떠올리는 단순한 방식,

- `지성 피부 → 제품 1`
- `건성 피부 → 제품 2`

처럼 1차원적으로 추천하는 서비스가 아니다.

실제로 사람들은 제품을 고를 때 여러 조건을 같이 본다.

- 피부 타입
- 최근 자극 여부
- 현재 루틴 안정성
- 메이크업 여부
- 아침/저녁 사용 시간
- 실내/실외 사용 상황
- 성분 민감도
- 제형 / 마감 / 밀림 / 백탁 / 눈시림 가능성

즉 이 서비스의 핵심은:

> **하나의 피부 타입에 하나의 제품을 붙이는 것**이 아니라,  
> **여러 조건을 순서대로 확인해서 후보를 좁히는 구조**를 만드는 것이다.

예를 들면:

> 지성 피부  
> → 조건 1. 최근 자극 없음  
> → 조건 2. 메이크업 위에 올릴 예정  
> → 조건 3. 야외 활동 많음  
> → 조건 4. 백탁 민감  
> → 제품 1, 제품 2, 제품 3

이 구조는 지금 MVP 범위에서도 유효하고, 이후 DB가 커질수록 더 확장 가능하다.

---

## 1. 이 서비스가 지금 도와주는 범위

이 서비스는 크게 3단계까지 도와준다.

1. 루틴 점검
2. 제품 루틴 점검
3. 국민템 / 기본템 중심의 큐레이션 추천

---

## 2. 범위 1 — 루틴 점검

이 단계는 “무슨 제품을 살지”보다 먼저,  
**지금 새 제품을 사는 게 맞는 상태인지**를 점검하는 영역이다.

### 2.1 다루는 항목

- 최근 따가움, 붉어짐, 가려움 같은 자극 여부
- 세안 방식이 안정적인지
- 선크림을 외출 시 바르는지
- 선크림을 덧바르는지
- 메이크업 제거를 따로 하는지
- 클렌징 폼 거품을 충분히 내는지
- 세안 후 당김/건조/따가움이 있는지
- 브러시 세척 주기
- 퍼프 사용 기간
- 배갯잎 교체 주기
- 잠들기 전 세안 여부
- 잠들기 전 루틴 여부

### 2.2 이 단계에서 서비스가 하는 일

- 제품 추천 전에 루틴 오류를 먼저 잡는다.
- “지금은 세럼보다 선크림 루틴이 먼저” 같은 우선순위를 준다.
- “지금은 새 제품보다 세안/위생/밤 루틴 점검이 먼저” 같은 gate를 준다.
- 제품 문제와 생활/위생 문제를 분리해준다.

### 2.3 이 단계의 핵심 가치

스킨케어 실패는 제품 성분 자체보다 아래 문제에서 더 자주 생긴다.

- 세안이 불안정함
- 메이크업 제거 부족
- 선크림 미사용
- 밤 루틴 누락
- 도구 / 침구 위생 불량

즉 이 서비스는 제품을 추천하기 전에  
**제품 외적인 루틴 문제까지 먼저 체크하는 서비스**다.

---

## 3. 범위 2 — 제품 루틴 점검

이 단계는 “어떤 제품이 좋나” 이전에,  
**지금 제품군의 역할과 사용 순서를 제대로 이해하고 있는지**를 점검하는 영역이다.

이 서비스는 단순히 제품명을 나열하지 않고,  
토너 → 세럼 → 보습제 → 선크림 같은 전체 흐름 안에서 제품을 본다.

### 3.1 다루는 질문

- 토너가 정말 필요한지
- 토너가 수분 토너인지, 각질 토너인지
- 세럼이 필요한지, 아니면 보습제/클렌저가 먼저인지
- 세럼을 여러 개 겹쳐 쓰고 있는지
- 보습제가 부족한지, 혹은 너무 무거운지
- 선크림을 마지막 단계로 쓰고 있는지
- 아침/저녁 시간대에 맞는 제품인지
- 메이크업과 궁합이 맞는지
- 레티놀/비타민C/AHA/BHA 같은 기능성 성분을 같이 쓰고 있는지
- 제품을 너무 자주/많이 쓰고 있지 않은지

### 3.2 사용 순서 / 빈도 / 용량에서 도와주는 범위

두 기준 문서에서 반복되는 범위까지는 서비스가 다룰 수 있다.

- 선크림은 주간 마지막 단계
- 선크림은 충분량 사용 + 재도포 여부 확인
- 레티놀은 야간 사용 / 점진적 도입
- 비타민 C는 아침 사용 권장
- 각질 토너는 매일이 아니라 주 1~3회 같은 빈도 조절
- 세럼은 한 번에 1~2개 정도로 제한하고 충돌 조합 경고
- 보습제는 세럼 뒤에서 수분 잠금 역할

즉 이 서비스는 단순 추천이 아니라  
**제품이 루틴 안에서 어떤 자리에 있어야 하는지**까지 설명한다.

### 3.3 이 단계의 핵심 가치

많은 사용자는 “좋은 제품”을 찾기 전에 아래에서 이미 꼬인다.

- 제품군 자체를 잘못 고름
- 같은 역할 제품을 너무 많이 씀
- 아침/저녁 사용 구분이 없음
- 순서가 엉킴
- 사용 빈도가 과함

그래서 이 서비스는 제품 추천보다 먼저  
**제품 루틴이 구조적으로 맞는지**를 본다.

---

## 4. 범위 3 — 국민템 / 기본템 중심 큐레이션 추천

루틴 점검과 제품 루틴 점검을 통과하면,  
그다음 단계에서 후보 제품을 좁혀준다.

이때 추천 방식은 “베스트 1개 확정”이 아니라  
**조건을 통과한 기본템 / 국민템 후보군을 좁히는 방식**이다.

### 4.1 추천 방식

예시:

- 건성 피부
- 최근 자극 있음
- 세안 후 당김 있음
- 메이크업 들뜸 있음

→ 보습 우선  
→ 저자극 / 장벽 / 메이크업 궁합 조건 적용  
→ 로션/크림 후보 1, 2, 3

또는:

- 지성 피부
- 야외 활동 많음
- 메이크업 자주 함
- 백탁 민감

→ 선크림 우선  
→ 경량 / 메이크업 궁합 / low white cast / 재도포 적합 조건 적용  
→ 선크림 후보 1, 2, 3

### 4.2 이 추천이 의미하는 것

이 서비스가 하는 추천은:

- “전 국민에게 제일 좋은 제품” 추천이 아니다.
- “이 피부 타입이면 무조건 이 제품” 추천도 아니다.

대신:

> **지금 상태와 조건을 통과한, 실패 확률이 낮은 기본템 / 국민템 후보를 좁혀주는 추천**

이다.

### 4.3 왜 국민템 / 기본템 영역부터 가능한가

현재 데이터와 문서 구조로도 아래는 비교적 안정적으로 설명 가능하다.

- 저자극 성향
- 제형 / 사용감
- 무기자차 / 유기자차
- 백탁 가능성
- 메이크업 궁합
- 장벽/보습 중심 여부
- 논코메도 지향 여부
- 야외 활동 적합성

즉 **기본적인 선택 기준이 분명한 제품군**은 큐레이션 가능하다.

## 5. 이 서비스가 지금 하지 않는 것

핵심 한계는 기능성 화장품의 “진짜 효능” 판정이다.

### 5.1 지금 자동으로 하지 않는 것

- 이 제품이 기능성 성분 기준을 완전히 충족하는지 자동 판정
- 이 제품이 실제로 효과가 강한지 정량 비교
- 전성분표만 보고 정확한 유효 농도를 확정
- “이 제품은 진짜 효과 있다 / 없다”를 엔진이 단정

### 5.2 왜 지금 분리하는가

현재 공개 데이터만으로는 아래가 어렵다.

- 완제품의 정확한 레시피 확인
- 개별 활성 성분의 실제 함량 확인
- 성분 간 조합과 안정화 수준 확인
- 제품별 실제 효과 강도 비교

즉:

- **기능성 화장품 여부 확인**은 일부 가능
- **기능성 성분이 충분히 들어 있는지**
- **실제로 효과가 어느 정도인지**

는 지금 단계에서 자동화하기 어렵다.

---

## 6. 큐레이터 책임으로 분리한 영역

그래서 현재 서비스는 아래를 **시스템의 자동 판정 책임**이 아니라  
**큐레이터의 책임 영역**으로 분리한다.

### 6.1 큐레이터 책임 영역

- 기능성 화장품 인정 여부 확인 후 라벨링
- 공개된 농도 정보가 있는 경우만 근거 메모 추가
- “효과 기대 가능”, “근거 약함”, “공개 정보 부족” 같은 설명 작성
- 성분표 기반 해석과 실제 사용 경험 사이의 간극 보정
- 국민템 / 기본템 후보 선정

### 6.2 서비스 엔진 책임 영역

- 루틴 점검
- 제품군 우선순위 판단
- 조건 기반 필터링
- 사용 순서 / 빈도 / 충돌 경고
- 생활/위생/루틴 문제 탐지

즉 현재 구조는:

> **효능 검증 엔진**이 아니라  
> **조건 기반 의사결정 엔진 + 큐레이터 보정 구조**

로 이해하는 것이 맞다.

---

## 7. 사용자가 체감하는 제품 가치

사용자 입장에서는 이 서비스가 아래를 도와주면 이미 가치가 있다.

### 7.1 “지금 뭘 먼저 해야 하는지” 정리

- 세럼을 더 사야 하는지
- 선크림부터 바로잡아야 하는지
- 세안 방식부터 고쳐야 하는지
- 위생 문제를 먼저 잡아야 하는지

### 7.2 “내 루틴이 맞는지” 정리

- 토너가 꼭 필요한지
- 수분 토너인지 각질 토너인지
- 세럼을 여러 개 겹치는 게 맞는지
- 선크림을 마지막에 쓰고 있는지
- 밤 루틴이 안정적인지

### 7.3 “너무 많은 제품 중에서 어디까지 좁혀야 하는지” 정리

- 내 피부 / 시간대 / 메이크업 / 야외 활동 / 민감도에 맞는 후보만 보기
- 실패 확률이 높은 제품군 먼저 제외
- 국민템 / 기본템 범위 안에서 시작하기

즉 이 서비스의 현실적인 강점은:

> **완벽한 효능 판정**이 아니라  
> **구매 전후의 판단 과정을 구조화해서 실패를 줄여주는 것**

이다.

## 8. 확장 가능성

현재는 기능성 필터링을 큐레이터 책임으로 분리했지만,  
이건 영구 한계라기보다 **현재 단계의 운영 경계**에 가깝다.

### 8.1 앞으로 확장 가능한 방향

- 제품별 공식 기능성 정보 DB 확장
- 제품별 성분표 DB 정교화
- 브랜드 공개 농도 수집
- 공개 근거 수준 테이블화
- 큐레이터 메모 / evidence note 구조화
- 사용자 반응 데이터 축적
- 제품별 루틴 적합도 / 실패 사례 누적

### 8.2 확장 후 가능해지는 기능

이후 DB와 운영 체계가 확장되면,  
지금은 어려운 아래 기능으로 갈 수 있다.

> **“이 화장품 괜찮나요?”**

이 질문에 대해 앞으로는 아래를 합쳐 답할 수 있다.

- 내 피부 타입과 맞는지
- 내 현재 루틴과 충돌하지 않는지
- 아침/저녁 사용 상황에 맞는지
- 메이크업 / 야외 활동 / 민감도에 맞는지
- 공식 기능성 정보가 있는지
- 공개 농도 정보가 있는지
- 큐레이터 기준에서 기본템/국민템으로 볼 수 있는지
- 유사 사용자 반응에서 문제 신호가 있었는지

단, 이 기능도 결국은 **확실한 정보 / 추정 / 확인 불가**를 나눠서 보여주는 방식으로 가야 한다.

---

## 9. 최종 정리

현재 이 서비스가 다루는 범위는 여기까지다.

1. 루틴 점검  
   배갯잎, 세안, 선크림, 도구 위생, 밤 루틴 같은 제품 외적 요소 포함

2. 제품 루틴 점검  
   토너 → 세럼 → 보습제 → 선크림의 전체 흐름, 순서, 빈도, 충돌, 용량/사용 습관 점검

3. 국민템 / 기본템 중심 큐레이션  
   다조건 필터를 통과한 후보군 추천

그리고 현재 한계는 분명하다.

- 기능성 화장품이 실제로 기준을 충족하는지
- 실제로 효과가 강한지
- 유효 농도가 충분한지

이 영역은 지금 **자동 판정하지 않고 큐레이터 책임으로 분리**한다.

하지만 구조는 열려 있다.

> 지금은 “조건 기반 루틴/제품 선택 서비스”이고,  
> 이후에는 DB 확장과 큐레이션 고도화를 통해  
> **“이 화장품 괜찮나요?”까지 답할 수 있는 서비스**로 확장할 수 있다.
