# 19 제품 전략 v2: Playbook Platform

_Product strategy, rewritten under 18_thesis_revision.md | Claude | 2026-08-19_

> 이 문서는 `11_product_strategy.md`를 폐기하고 대체한다.
> 전제는 18번 문서의 결론이다: 문제는 출발 전 결정 과잉이 아니라 **현장에서 계획이 휘발되는 것**이다.

## 1. Core Product Concept

> **"여행 계획을 대신 세워주는 서비스가 아니라, 계획이 무너지는 현장에서 당신의 3주치 준비를 3초 만에 꺼내주는 서비스."**

핵심은 `계획 대행`도 `결정 축소`도 아니다. **준비의 형태 변환**이다.

사용자는 이미 3주 동안 준비했다. 저장 핀 40개, 블로그 스크랩, 인스타 컬렉션, AI가 뽑아준 초안. 문제는 그 준비물이 **현장에서 쓸 수 없는 형태**라는 것이다. 시간 순으로 나열된 일정표와 정렬 없는 저장 목록은, 비 오는 화요일 오후 3시에 배고픈 상태로 서 있는 사람이 열어볼 수 있는 물건이 아니다.

이 제품은 그 준비물을 **조건으로 꺼낼 수 있는 형태(플레이북)** 로 바꾸고, 현장에서 대신 꺼내준다.

---

## 2. 전략의 출발점: 우리는 새 노동을 요구하지 않는다

이것이 이 제품의 가장 중요한 전략적 선택이다.

18번 문서가 식별한 최대 실행 리스크는 닭-달걀 문제였다. 현장 가치는 준비된 사람에게만 나오는데, 준비를 시키려면 현장 가치를 먼저 보여줘야 한다.

**해법은 준비를 새로 시키지 않는 것이다.**

| 접근                       | 사용자 요구 노동         | 성공 가능성 |
| -------------------------- | ------------------------ | ----------- |
| "우리 앱에서 계획하세요"   | 3주치 계획을 다시 입력   | 매우 낮음   |
| "조건 태그를 붙이세요"     | 40개 × 6개 축 수동 태깅  | 낮음        |
| **"이미 만든 걸 가져오세요"** | **링크 붙여넣기 1회**  | **높음**    |

그래서 제품의 진입점은 계획 도구가 아니라 **변환기(Converter)** 다.

```
구글맵 저장 리스트  ┐
인스타 저장 컬렉션  │
블로그 / 유튜브 링크 ├──→  [변환]  ──→  조건 인덱스 플레이북
AI가 뽑아준 일정 초안│                    (자동 태깅 + 사용자 확인)
트리플 / 노션 일정표 ┘
```

사용자 입장의 가치 제안이 이렇게 바뀐다.

> ~~"우리 서비스로 여행을 계획하세요"~~
> **"이미 저장해둔 40개, 현장에서 못 쓰고 있죠. 붙여넣기 한 번이면 쓸 수 있게 바꿔드립니다."**

이는 신규 서비스의 최대 장벽인 `전환 비용`을 우회한다. 기존 도구(구글맵·트리플·인스타)와 경쟁하지 않고 그 산출물을 입력으로 받기 때문이다.

## 3. 2-Mode 구조

제품은 두 모드를 가지며, 하나의 자산(플레이북)을 공유한다.

### Prep 모드 (출발 전, 저관여)

- **목적:** 흩어진 준비물을 플레이북으로 변환
- **사용 빈도:** 여행당 3~8회, 짧게
- **핵심 원칙:** 사용자 입력 최소화. 자동 태깅이 하고, 사람은 확인·우선순위만
- **산출물:** 조건별로 꺼낼 수 있는 옵션 세트 + 오프라인 캐시

### Live 모드 (여행 중, 고관여)

- **목적:** "지금 뭐하지"에 3초 안에 답하기
- **사용 빈도:** 여행당 60~150회 (하루 15~30회)
- **핵심 원칙:** 질문하지 않는다. 열면 이미 답이 있다
- **산출물:** 선택 로그 (다음 제시와 데이터 자산의 원천)

두 모드의 관계가 이 제품의 정체성이다. **Prep은 Live를 위해서만 존재한다.** Prep 모드가 그 자체로 훌륭한 계획 도구가 되려는 순간, 제품은 다시 트리플·Wanderlog와 같은 게임을 하게 된다.

## 4. 포지셔닝: 여정 축으로 다시 그린 지도

09 문서의 포지셔닝 맵(발견↔예약, 영감↔정리)은 출발 전 세계만 그린 지도였다. 여정 축으로 다시 그리면 공백의 위치가 다르다.

```
        발견        계획        예약     │   현장(In-Trip)   │   기록
        ────        ────        ────     │   ────────────    │   ────
유튜브   ●                               │                   │
블로그   ●           ○                   │                   │
트리플              ●           ○        │                   │
Wanderlog           ●                    │                   │
스카이스캐너                    ●        │                   │
야놀자/아고다                   ●        │                   │
마이리얼트립         ○          ●        │        ○          │
GetYourGuide                    ●        │        ◐          │  ← 상품만
구글맵               ○                   │        ●          │  ← 맥락 없음
인스타/사진                              │                   │    ●
                                         │                   │
                                    ┌────┴───────────────────┴────┐
                                    │  여기가 비어 있다             │
                                    │  = 내 준비 × 현장 조건        │
                                    └──────────────────────────────┘
```

현장 칸을 점유한 두 플레이어의 결함은 서로 다르고, 둘 다 구조적이다.

**구글맵 — 현장을 소유했지만 내 여행을 모른다**
내가 3주간 저장한 40개 핀도, 동행이 5세 아이라는 것도, 어제 라멘을 먹었다는 것도, 오늘 오전 일정이 40분 밀렸다는 것도 모른다. 평점순 일반 결과를 준다. 구글맵의 인센티브는 전 세계 범용 지도이지 특정 여행의 맥락이 아니다.

**GetYourGuide·Klook — 현지에 있지만 팔 수 있는 것만 보여준다**
무료 공원, 걷기 좋은 골목, "지금은 아무것도 하지 말고 숙소에서 쉬어라"는 이들의 상품 목록에 존재할 수 없다.

> **내 일정표는 현장을 모르고, 현장의 도구는 내 여행을 모른다.**

## 5. Differentiation

| 대상             | 그들이 답하는 질문                  | 우리가 다른 지점                                   |
| ---------------- | ----------------------------------- | -------------------------------------------------- |
| 구글맵           | 이 근처에 평점 높은 곳은            | **내가 저장한 것 중** 지금 조건에 맞는 곳          |
| 트리플·Wanderlog | 담은 장소를 어떻게 정리하나         | 정리 결과를 **현장에서 꺼낼 수 있게** 변환         |
| GetYourGuide     | 지금 예약 가능한 상품은             | 예약 안 해도 되는 답, **쉬라는 답**까지 포함       |
| ChatGPT·AI 플래너 | 그럴듯한 일정 초안                  | 그 초안을 **조건 인덱스로 변환**해 현장에서 씀     |
| 패키지 여행      | 전부 대신 결정                      | 결정권은 두고 **꺼내는 비용만** 없앰               |

### 세 가지 구조적 차별점

**1. Condition-indexed, not time-indexed**
산출물이 일정표가 아니라 플레이북이다. 시간 인덱스는 첫 이탈에서 전부 무효화되지만, 조건 인덱스는 이탈 자체를 입력값으로 받는다.

**2. Your prep, not generic results**
현장에서 보여주는 후보는 우리가 고른 것이 아니라 **사용자가 이미 고른 것**이다. 신뢰의 원천이 알고리즘이 아니라 본인의 과거 판단이라는 점이 결정적이다.

**3. Deferred decision, prepared retrieval**
결정을 앞당기지 않고 미룬다. 대신 미뤄진 결정이 최악의 조건(피로·시간압박·로밍)에서 내려지지 않도록 꺼내는 비용을 0에 가깝게 만든다.

## 6. MVP 범위 — 왜 도보 밀집 도시인가

11 문서는 목적지 5곳(오사카·도쿄·후쿠오카·다낭·방콕)을 제안했다. 새 논지에서는 **선정 기준 자체가 달라진다.**

Live 모드의 핵심 가치는 "지금 여기서 도보 10분 내 대안 3개"다. 이 가치가 성립하려면 목적지가 다음 조건을 만족해야 한다.

| 조건                  | 이유                                           |
| --------------------- | ---------------------------------------------- |
| **도보 밀집도가 높다** | 도보 10분 내 대안이 실제로 존재해야 함         |
| **실내외 분기가 뚜렷** | 비/더위 조건이 의미 있는 분기를 만들어야 함    |
| **영업시간·휴무 변수** | 조건 필터가 실제로 후보를 걸러야 함            |
| **한국인 반복 방문**   | 저장 핀 자산이 이미 쌓여 있어야 함             |

이 기준으로 보면 **차량 이동 중심 목적지(방콕·다낭)는 초기 검증에 부적합하다.** 이동이 차량 기반이면 "도보 10분 내 대안"이 성립하지 않아 제품의 핵심 가설을 검증할 수 없다.

### 수정된 초기 범위

1. 오사카
2. 도쿄
3. 후쿠오카
4. 교토

일본 4개 도시. 도보·대중교통 밀집, 실내외 분기 명확, 휴무·영업시간 변수 큼, 한국인 재방문율 최상위. 방콕·다낭은 도보 가설 검증 이후 확장한다.

**중요한 차이:** 이전 결론에서는 목적지별 판단 데이터(Decision Card 25종)를 수동 시딩해야 했다. 새 구조에서는 후보의 원천이 **사용자의 저장 핀**이므로 목적지별 콘텐츠 시딩 부담이 훨씬 낮다. 우리가 시딩할 것은 장소가 아니라 **조건 판정 규칙**(실내외 분류, 소요시간 추정, 유아차 접근성 등)이며 이는 목적지 무관하게 재사용된다.

이는 새 논지가 실행 난이도까지 낮춘다는 뜻이다.

## 7. Cold Start

### Step 1: 변환기를 단독 진입점으로 만든다

첫 사용자 가치는 "구글맵 저장 리스트를 붙여넣으면 조건별로 정리해 준다"이다. 계정도, 계획도, 목적지 설정도 필요 없다. 이 단계까지가 무료이자 유입면이다.

### Step 2: 첫 여행에서 Live 모드를 강제로 만나게 한다

여행 시작일에 알림 하나. "오늘 오사카죠. 지금 뭐하지 버튼 눌러보세요."
Live 모드의 첫 성공 경험(3개 중 하나를 실제로 갔다)이 리텐션의 전부다.

### Step 3: 선택 로그가 쌓이면 제시 품질이 올라간다

같은 사용자의 2일차는 1일차 선택을 반영한다. 여행 1회 안에서 개인화가 체감되어야 한다. 여행 간 간격이 길기 때문에 **여행 내 학습**이 여행 간 학습보다 중요하다.

### Step 4: 하지 말아야 할 것

- 자체 장소 데이터베이스 구축 (사용자 저장 핀 + 지도 API로 충분)
- 목적지별 큐레이션 콘텐츠 제작 (다시 미디어가 된다)
- Prep 모드를 본격 계획 도구로 확장 (트리플과 같은 게임)
- 현장에서 긴 설문·설정 요구

## 8. 수익 원칙

### Principle 1: In-destination이 자연스러운 수익 지점이다

액티비티 예약과 지출의 무게중심은 이미 현지로 이동했고, 그 순간에 사용자 맥락을 아는 주체는 없다. "지금 이 줄은 40분이고, 스킵 티켓이 있다"는 판단의 일부이지 광고가 아니다.

### Principle 2: "쉬어라"가 결론일 수 있어야 한다

이 원칙이 무너지는 순간 제품은 GetYourGuide가 된다. 무료 옵션, 아무것도 안 하는 선택지가 항상 후보에 포함되어야 하고, 제휴 상품은 시각적으로 분리되어야 한다.

### Principle 3: 여행 단위 과금이 구독보다 자연스럽다

연 2회 사용 제품에 월 구독은 맞지 않는다. `여행 1회 패스` 또는 Prep 무료 / Live 유료 구조가 사용 패턴과 일치한다.

---

## 9. 이 제품이 명시적으로 하지 않는 것

- 시간 단위 일정표를 최종 산출물로 만들지 않는다 (붕괴하는 구조를 재생산하지 않는다)
- 일정을 생성해 주지 않는다 (생성은 어디서 하든 좋고, 우리는 변환한다)
- 장소 데이터베이스를 소유하려 하지 않는다
- 여행 영감·트렌드 피드를 만들지 않는다
- 현장에서 스크롤이 필요한 화면을 만들지 않는다
- 예약·결제를 자체 처리하지 않는다 (MVP 기준)

## 10. 성공 지표

| 계층       | 지표                              | 의미                                    |
| ---------- | --------------------------------- | --------------------------------------- |
| **핵심**   | 현장 구글맵 이탈률                | 우리 화면을 보고도 구글맵을 켜면 실패   |
| 핵심       | 제시 3개 중 선택률                | 맥락 적중도                             |
| 핵심       | 여행 2일차 이후 잔존율            | 첫날 실망 여부 (가장 냉정한 지표)       |
| 보조       | 여행 1일 평균 Live 실행 횟수      | 현장 습관 형성                          |
| 보조       | 변환 완료율 (붙여넣기 → 플레이북) | 진입 장벽                               |
| 보조       | "다 별로" 비율                    | 후보 품질 (높으면 태깅/필터 문제)       |

가장 중요한 것은 첫 번째다. 이 제품의 경쟁자는 트리플이 아니라 **구글맵을 켜는 손가락**이다.

## Strategy Summary

| Dimension         | Decision                                              |
| ----------------- | ----------------------------------------------------- |
| Core question     | (출발 전) 무엇을 결정할까 → **(현장) 지금 뭐하지**    |
| First wedge       | **변환기** — 저장 핀·초안을 플레이북으로              |
| Core artifact     | 시간 인덱스 일정표 → **조건 인덱스 플레이북**         |
| Core data model   | **현장 선택 로그** (맥락 확정 상태의 revealed choice) |
| Trust model       | 알고리즘 추천이 아니라 **본인의 과거 판단**           |
| Initial scope     | 도보 밀집 4개 도시 (오사카·도쿄·후쿠오카·교토)        |
| Growth surface    | 변환기 단독 사용 + 여행 시작일 알림                   |
| Revenue principle | in-destination 연결, 단 "쉬어라"가 가능해야 함        |
| Real competitor   | **구글맵을 켜는 손가락**                              |

## Closing Statement

여행 산업 전체가 버려질 산출물을 더 잘 만드는 일에 최적화되어 있다. 18시간을 들여 만든 일정표는 92%의 확률로 어긋나고, 그 순간 사용자는 자기 여행을 전혀 모르는 구글맵으로 돌아간다. 3주치 준비가 그 자리에서 증발한다.

이 제품의 전략은 더 좋은 계획을 만드는 것이 아니다. **이미 만들어진 계획이 현장에서 살아남게 만드는 것**이다.
